# 项目定义

## 一句话说明

`pdf-orc` 是一个运行在浏览器里的本地 PDF 案卷整理工具：把多份扫描件合并成一份、按页浏览、拖动排序、旋转/删除/插入页面，最终导出一份顺序正确的 PDF。首个目标场景是交通事故案卷材料整理。

## 目标用户与核心任务

- 用户：办理交通事故案件的律师、法律从业者与当事人。
- 输入：多份 PDF 扫描件（事故认定书、现场勘查笔录与图、当事人身份证件、驾驶证、保险单据、医疗与赔偿凭证、调解/诉讼文书等）。
- 核心任务：把散乱的案卷扫描件合并、按页整理顺序、修正页面方向，导出一份可直接提交或归档的 PDF。
- 价值：替代"打印 → 手工排序 → 重新扫描/合并"的繁琐流程；整理过程可视化、可撤销，降低出错成本。

## 当前产品范围

### 核心流程

1. 导入：选择一份或多份本地 PDF，或粘贴扫描全能王分享链接（经本地桥接服务下载，见 ADR 0009），解析页数后全部追加到统一页面列表。
2. 阅读模式：左侧缩略图栏 + 右侧大图查看，点击缩略图跳转（类似 macOS 预览器）。
3. 页面管理模式：较大缩略图网格，可看清每页内容；多选（单击 / Cmd / Shift）+ 拖动单页或选中组排序；hover 显示旋转/删除操作；左侧分组面板把页面按证据类别分组与筛选。
4. 撤销/重做贯穿所有编辑操作。
5. 导出：按当前页面顺序与每页旋转状态生成新 PDF 并下载。

### 双视图与分组（律师证据整理场景）

- 两个顶层视图：**阅读**（细看单页内容）与**页面管理**（同屏统一组织多页），一键切换。
- 分组 = 给页面打证据类别标签（事故认定书、现场照片、当事人证件、保险单据、医疗票据、调解文书等）；分组不强制顺序，最终顺序仍由拖动决定。
- 分组为后续「卷内目录生成」打基础（见扩展方向）。

### 功能优先级（版本计划）

| 版本 | 内容 |
|---|---|
| v0.1（MVP） | 双视图切换、多源导入（本地 PDF + 扫描全能王分享链接）、阅读模式、页面管理（大缩略图网格、多选、单页/选中组拖动排序、hover 旋转/删除、分组标签与筛选、页面拼合）、撤销/重做、导出下载 |
| v0.2 | 插入页面（从其他 PDF / 空白页）✅、N 页拼合与「裁剪到标准卡尺寸」、批量操作强化 |
| v0.3 | 导出页码标注、卷内目录生成、空白页/重复页检测 |
| 后续 | 见「扩展方向」 |

### 明确不在当前范围

- OCR 文字层与全文搜索。
- AI 自动分类/分组建议。
- 任何服务端存储、云同步、多人协作、账号体系。
- 页内内容编辑（标注、涂黑、签名、文字修改）。
- 打印流程（使用系统打印能力）。
- 非 PDF 格式转换（图片/Word 等需用户先转换为 PDF）。

## 领域规则

- 输出 PDF 的页面顺序严格等于当前页面列表顺序（所见即所得）。
- 每页独立维护旋转角（0/90/180/270），导出时应用；源文件永不被修改。
- 编辑操作（排序/旋转/删除/插入/分组）均可撤销；撤销栈默认上限 100 条（可配置）。
- 页面列表是唯一事实源：阅读视图、管理视图与导出都只消费同一个列表。
- 分组是「证据类别标签」：同组页不必连续，最终顺序由用户拖动决定；改名/删除分组只改标签，不动页序。
- 案卷常见顺序仅作参考（如：接警记录 → 事故认定书 → 现场勘查笔录与图 → 检验鉴定意见 → 当事人身份与证件 → 保险单据 → 赔偿/调解文书），工具不做强制排序，顺序完全由用户决定。

## 扩展方向（设想，按需立项）

- 卷内目录（证据目录）生成：按用户分组自动生成目录页（分组名 + 起始页码），符合诉讼案卷归档习惯。
- 导出页码：每页底部居中标注页码。
- 空白页/重复页检测：提醒双面扫描常见的空白页与重复页。
- OCR 文字层与全文搜索：识别后支持关键词搜索、结果跳页。
- AI 页面类型识别（现场照片/文书/证件/单据）→ 自动分组与排序建议。
- 子集导出：选中页面单独导出。
- 版本对比：两份案卷 PDF 的页面差异核对。
- 与既有 camscanner 工作流衔接（按证据目录提取指定页面）的能力，仅在用户确认后立项。

当两个以上能力开始共享"分组/标签"数据结构时，再上移为公共模型；不要提前构建无法验证的通用案卷平台。

## 成功标准

- 能导入 3–5 份事故案卷扫描件并合并预览。
- 单份 100+ 页扫描件、多份合并数百页的场景下：阅读模式翻页接近系统预览器，无明显卡顿；管理模式网格滚动、拖动排序、多选与批量操作流畅。
- 导出的 PDF 页序、旋转与界面所见一致（WYSIWYG）。
- 所有编辑可撤销/重做，撤销后状态与操作前一致。
- 全程无服务端：无上传、无网络请求（构建产物本地运行）。
