# 工程约定

## 修改原则

- 先明确行为边界，再修改实现；不要用 UI 隐藏代替删除废弃能力。
- TypeScript 保持严格类型，不用 `any` 绕过 pdf.js / pdf-lib 类型问题。
- 组件负责展示和交互；PDF 解析、渲染、导出分别留在对应边界。
- 错误信息使用可操作的中文，说明用户需要检查的文件或操作条件。
- 优先保留稳定的渲染/导出基础设施；当旧编排层与新产品流程冲突时，允许直接重写编排层。

## 文档核心约定

- `PageList` 是唯一事实源；任何视图与导出都不得持有自己的页面顺序副本。
- 所有编辑必须通过命令（可逆）提交，不允许直接修改状态数组。
- 命令是纯数据、可序列化；连续同类操作可合并，但合并必须保持撤销语义正确。
- 页面 id 稳定（自增或 uuid），跨会话恢复（IndexedDB 备份）时保持不变。

## 渲染约定

- pdf.js worker 全局单例；DocumentRef 的打开/关闭走统一入口。
- canvas 渲染只能发生在 effect 或事件处理器中，禁止在渲染期同步执行。
- 缓存键必须包含 `source:page:rotation:scaleBucket`；页面旋转变化必须使缓存失效。
- 缩略图缓存设 LRU 上限；命中率作为性能观测指标。
- 全尺寸 canvas 数量必须最小化：阅读模式同一时刻不超过 3 个，离开视口即释放；缩放一律重渲染，禁止拉伸 canvas。
- 缩略图统一低分辨率渲染；管理网格与缩略图栏必须虚拟滚动，只渲染可见项。

## 导出约定

- 导出永远基于当前 PageList 全量重建；绝不修改源文件。
- 每页旋转在导出时应用；导出结果必须与界面所见一致（WYSIWYG 为测试项）。
- 导出错误不得静默吞掉：明确提示是哪一页、哪一份源文件导致的失败。

## 交互约定

- 管理模式遵循"先选中后拖动"的直觉：未选中页拖动 = 移动单页；选中组拖动 = 整组移动。
- hover 操作按钮（旋转/插入/删除）不得与拖动事件冲突（事件阻止策略）。
- 删除、批量操作必须保留撤销入口；不可逆操作（如覆盖同名导出文件）前明确提示。

## 测试约定

每次交付至少执行：

```bash
npm run test
npm run build
npm run lint
git diff --check
```

纯逻辑测试优先覆盖：

- 命令应用与逆操作（排序/旋转/删除/插入/合并）。
- reorder 边界：单页、多选组、移动到首/尾、跨源合并。
- 撤销/重做：连续操作、合并命令、撤销后再操作（future 清空）。
- 导出页序映射：PageList → 目标 PDF 页序与旋转。
- LRU 缓存命中与淘汰。
- 源注册表：惰性加载、释放、重复 id。

手工验证项：

- 真实扫描件（照片、证件、文书混合）全流程。
- 200+ 页性能。
- 含 JPEG2000/CCITT 编码的扫描件导出兼容性。
- 浏览器刷新后 IndexedDB 会话恢复（如实现）。

## Hermes 文档约定

- `project.md` 保存长期产品边界；`architecture.md` 保存当前结构和数据流；`conventions.md` 保存施工规则和验证门槛；`current.md` 保存当前交付状态与未完成验证。
- 重要取舍新增 ADR；旧 ADR 不回写结论，变化通过新 ADR 取代。
