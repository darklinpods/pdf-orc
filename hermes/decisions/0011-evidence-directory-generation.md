# ADR 0011：证据目录自动生成采用「桥 OCR + 规则分类 + 标签派生」

- 状态：已接受
- 日期：2026-08-20

## 背景

用户希望「根据文档内容自动生成一份证据目录，可修改，然后按目录给页面打标签分组」。关键约束：案卷是敏感法律材料，分类必须**离线、不联网、隐私安全**；用户已确认「只打标签、不做重排」。

## 决策

分四步，每步一个边界：

1. **OCR（本地桥）**：扩展 ADR 0009 的桥，新增 `POST /ocr`（原始 PDF 字节 body），复用 camscanner 技能的 `camscanner-ocr.py`（PyMuPDF 渲染 + macOS Vision 识别，环境已就绪）。前端逐源 OCR 后按 PageList 顺序还原每页文字。

2. **规则关键词分类（纯函数）**：`src/evidence/classify.ts`，按关键词表把每页 OCR 文本归入证据类别（事故认定书/身份证/驾驶证/保险单/医疗材料/司法鉴定/证明文件/起诉状/现场照片/证据目录…），无匹配归「未分类」。离线、零依赖、可单测。

3. **生成草稿目录**：相邻同类别页合并为一个目录项 `{名称, 起页, 止页}`；未分类页也成项（便于用户后续改）。

4. **校对 + 应用**：弹窗展示可编辑目录（改项名/页码范围/增删）；确认后按目录给每页 `relabel`（复用 ADR 0008 标签模型，一步撤销）。不重排页序。

## 影响

- 优点：离线、免费、案卷内容不出本机；分类规则是纯函数、可单测、可演进；应用走既有 relabel，撤销开箱即用。
- 代价：规则分类对模糊页精度有限（靠用户校对兜底）；OCR 依赖 macOS Vision（仅 macOS 环境，符合硬件基线）。
- 约束：
  - 桥 `/ocr` 仅本机；OCR 文本不落盘到 git（临时文件用完即删）。
  - 分类规则顺序即优先级（先匹配先得）；新增类别需补测试。
  - 目录只用于打标签，不用于重排（未来若要按目录重排，另立 ADR）。
- 验证：`classifyPage` / `buildDirectory` 单测；桥 `/ocr` 用真实样本 curl 验证；前端「生成→校对→应用」浏览器手工验证。
