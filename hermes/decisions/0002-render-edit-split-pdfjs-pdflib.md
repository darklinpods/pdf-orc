# ADR 0002：渲染与编辑职责分离——pdf.js 渲染、pdf-lib 导出

- 状态：已接受（待用户评审）
- 日期：2026-08-19

## 背景

浏览器内处理 PDF 是"渲染"与"编辑/导出"两个不同问题。pdf.js 是渲染的事实标准（众多预览器的内核），但只读，不能生成"页面重排/旋转/合并后的新 PDF"。页面管理需要写 PDF 的能力。备选：PDFium/WASM（渲染+编辑一体，集成成本高）、pdf-lib（纯 JS 读写，页面复制/旋转/合并 API 成熟）。

## 决策

- 渲染层用 pdf.js（Web Worker 渲染页面与缩略图）。
- 导出层用 pdf-lib（按 PageList 复制页、应用旋转、合并、写元数据）。
- 两者都只与文档模型（PageList）交互，互不感知，不直接互相调用。

## 影响

- 优点：各自使用最成熟的方案；纯前端、无 native 依赖；渲染与导出可独立演进。
- 代价：pdf-lib 重新序列化可能改变文件体积；JPEG2000/CCITT/JBIG2 编码页面可能复制失败或降级。
- 约束：开工首个 spike 必须用真实案卷扫描件验证兼容性与体积变化；失败时给出明确中文错误，并提示"打印为 PDF"折中路径。
- 验证：真实扫描件（含照片、证件、文书）导出后内容与页序正确。
