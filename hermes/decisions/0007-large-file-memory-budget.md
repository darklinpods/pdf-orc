# ADR 0007：大文件（100+ 页）渲染与内存预算策略

- 状态：已接受（待用户评审）
- 日期：2026-08-19

## 背景

用户反馈案卷扫描件单份可能 100+ 页；多份合并后总页数数百页，单份文件可达数百 MB。浏览器内存与 canvas 显存是硬约束：一张全尺寸 A4 扫描页的 canvas 约 30+MB，若全量渲染或缓存失控，数百页文档会直接压垮标签页。

## 决策

- 全尺寸 canvas 数量最小化：阅读模式同一时刻最多 3 个（当前页 ± 前后各 1 页预取），离开视口即释放。
- 缩放一律按目标 scale 重渲染，禁止 canvas 拉伸（拉伸大图占显存且糊）。
- 缩略图统一低分辨率渲染（约 160–220px 宽），LRU 缓存上限默认 300 张（按内存预算折算，可配）。
- 管理网格与阅读模式缩略图栏均虚拟滚动，只渲染可见项。
- pdf.js 单 worker；源 ArrayBuffer 通过 transferable 移交，避免主线程/worker 间复制。
- 单份文件过大（>300MB）时提示用户，不静默加载；导出数百页显示进度。

## 影响

- 优点：数百页场景可流畅阅读、排序与导出；内存占用可控。
- 代价：canvas 复用与缓存键管理更复杂；虚拟滚动与 dnd-kit 拖动需配合验证（滚动中拖动）。
- 约束：缓存失效必须覆盖旋转变化；LRU 上限、canvas 数量上限为性能观测指标，命中率纳入验收。
- 硬件基线（用户确认 2026-08-19）：macOS、16GB 内存起步。此预算下 LRU/缓存上限可适当放宽（如缩略图 500+ 张），但懒渲染、canvas 数量上限、虚拟滚动等策略不变。
- 验证：真实 100+ 页扫描件在阅读/管理/导出全流程的内存峰值与流畅度；拖动画面的虚拟滚动不抖动。
