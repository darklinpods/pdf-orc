# ADR 0008：分组采用「标签派生」轻量模型，不引入独立 Group 实体

- 状态：已接受
- 日期：2026-08-20

## 背景

用户（律师）需要把交通事故案卷证据按类别分组（事故认定书、现场照片、当事人证件、保险单据、医疗票据、调解文书等），以便在同一屏统一组织管理，并为后续「卷内目录」打基础。

分组有两种实现路线：
1. 独立 Group 实体（`DocumentState.groups` + PageRef 存 groupId + add/rename/deleteGroup 命令）。
2. 标签派生：PageRef 已有一个 `label` 字段，分组即「标签」——组列表从页面 label 去重派生，颜色由组名哈希到调色板，改名/删除 = 批量 relabel。

## 决策

采用标签派生模型：
- `PageRef.label` 存组名（`string | null`），复用现有 `relabel` 命令完成分组/改名/删除（撤销语义已具备）。
- 组列表从页面 label 去重派生（`collectGroups`），不单独存储。
- 组颜色由组名哈希到固定调色板（`groupColor`），零额外状态、稳定一致。
- 分组不强制顺序：同组页不必连续，最终导出顺序仍由用户拖动决定。

## 影响

- 优点：零新状态、复用已测试的 relabel 命令、撤销/重做开箱即用、实现最快。
- 代价：改名需整组 relabel（一次命令，开销可忽略）；不同组名可能哈希到同色（罕见，可接受）；分组无独立元数据（如排序权重、描述）。
- 约束：当需要分组的排序权重、目录生成或组级描述时，再上移为独立 Group 模型（遵循 project.md「由真实共享需求驱动抽象」原则），以新 ADR 取代本决策。
- 验证：`collectGroups`/`groupColor`/`relabelPagesCommand` 纯函数测试；分组、改名、删除的撤销/重做往返。
