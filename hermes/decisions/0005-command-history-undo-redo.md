# ADR 0005：所有编辑操作走命令模式，撤销/重做为刚需

- 状态：已接受（待用户评审）
- 日期：2026-08-19

## 背景

案卷排序整理误操作频繁（拖错位置、删错页、转错方向），撤销是刚需而非可选项。同时，可逆的编辑日志天然是 IndexedDB 会话备份（ADR 0004）的序列化来源，也是未来审计/协作的基础。

## 决策

- 所有编辑以可逆 Command（纯数据）提交，reducer 应用；禁止直接修改状态数组。
- history 栈维护 `past` / `future`；撤销 = 弹栈并执行逆操作，重做 = 重放。
- 连续同类命令（如连续旋转 3 次）允许合并为一条历史，但必须保持撤销语义正确。
- 撤销栈默认上限 100 条（可配置），防止内存无限增长。

## 影响

- 优点：撤销/重做语义统一；文档状态可序列化（备份恢复直接可用）；UI 与文档解耦。
- 代价：新增每种操作必须先实现逆操作，开发成本略增。
- 约束：命令必须纯、可逆；合并策略不得破坏单步撤销的直觉。
- 验证：命令应用/逆操作、连续操作、合并命令、撤销后再操作（future 清空）均有测试覆盖。
