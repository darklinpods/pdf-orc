## 用户反馈（2026-08-19）

- 案卷扫描件单份可能 **100+ 页**，多份合并后数百页，单份文件可达数百 MB。
- 已据此更新架构渲染策略（内存预算）、约定与成功标准，并新增 ADR 0007；性能基线按此设定。

## 已确认决策（2026-08-19，用户全部按默认值通过）

1. 多源合并进入 MVP（案卷整理天然多文件，排序价值依赖合并）。
2. 旋转/删除/插入为 P1（v0.2）；MVP 只做排序。
3. 分组标签提前到 P1。
4. 产品名称暂用工作区名 `pdf-orc`。
5. 浏览器目标：现代 Chrome/Edge/Safari，不做旧版兼容。
6. 性能基线：单份 100+ 页、合并数百页流畅（ADR 0007）。

## 硬件基线（2026-08-19）

- 用户运行环境：macOS，内存 **16GB 起步**；更低内存设备不在考虑范围。
- 影响：ADR 0007 的 LRU/缓存上限可在内存预算内适当放宽，但懒渲染、canvas 数量上限、虚拟滚动等策略不变。

## 开工后首个里程碑（spike）

- 用真实事故案卷扫描件（含 100+ 页）验证 pdf.js 渲染 + pdf-lib 复制/旋转/合并的兼容性、体积变化与内存峰值。此结果决定导出策略细节与性能基线（见 ADR 0002、ADR 0007 与 architecture.md 风险清单）。

## 下一步（设计评审通过后）

1. 脚手架：Vite + React 19 + TS + Tailwind + Vitest（git init 一并完成）。
2. 文档核心：类型、reducer、命令、历史栈 + 纯逻辑测试（先行）。
3. 渲染边界：pdf.js worker 单例、PageRenderer、缩略图 LRU 缓存。
4. 阅读视图：缩略图栏 + 大图 + 缩放/跳页。
5. 管理模式：dnd-kit 排序、多选、hover 操作、工具栏。
6. 导出边界：exporter + WYSIWYG 验证。

## 关注点

- pdf-lib 对扫描件编码的兼容性必须 spike 先行，避免导出阶段才发现不可用。
- 无服务端 = 所有持久化取舍围绕"最终下载交付"展开。
- 200+ 页性能目标依赖懒渲染与缓存，管理网格不得全量渲染。
